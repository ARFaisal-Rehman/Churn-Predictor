2. What "churn" means here

At a snapshot date D, a customer is active if they bought something in the {{ d.active_lookback_days }} days before D. An active customer has churned if they make no purchase in the {{ d.prediction_window_days }} days from D. Features use only transactions strictly before D, so the label can't leak into the inputs.

3. Snapshots and the out-of-time test

Instead of one snapshot with a random split, the model learns from {{ d.snapshots.train|length }} monthly snapshots and is tested on a later period it never saw. Each snapshot's {{ d.prediction_window_days }}-day label window closes before the next stage starts.

4. Features

{{ m.n_features }} behavioural features per customer: recency and how overdue they are against their own buying rhythm; order counts, spend and products in the last 30/60/90/180 days; order value statistics; tenure; returns; and spend trend. Heavy-tailed money and count features are log-scaled.

5. Choosing the model

Four candidates are compared by forward-chaining cross-validation: each of the last four training snapshots is predicted by a model trained only on snapshots whose label window had already closed. The best mean ROC-AUC wins. The test snapshot plays no part in this choice.

Why forward CV? An earlier version used folds grouped by customer, which still mixed periods. Adding "season of year" features raised that CV score by about 0.02, while the selected model's out-of-time AUC fell from 0.757 to 0.741: the folds were rewarding memorised seasons. Under forward CV the season features added 0.0006, which is noise, so they are off by default (USE_SEASON_FEATURES=1 turns them on).

6. Calibration

The chosen model is calibrated on the calibration snapshot, a later period than any training data. Sigmoid (Platt) and isotonic calibration are compared by 5-fold log loss inside that snapshot ({% for k, v in m.calibration_cv_log_loss.items() %}{{ k }} {{ v }}{% if not loop.last %}, {% endif %}{% endfor %}); {{ m.calibration_method }} was chosen. Isotonic can overfit a few thousand rows and output hard 0% or 100% probabilities, which is why it is not assumed. On the test period: Brier score {{ "%.3f"|format(ev.brier_uncalibrated) }} before and {{ "%.3f"|format(ev.brier_calibrated) }} after, against {{ "%.3f"|format(ev.brier_base_rate) }} for always predicting the base rate.

Limitation. The calibration window churned at {{ "{:.0%}".format(d.churn_rate.calibration) }}, while the pre-Christmas test window churned at {{ "{:.0%}".format(d.churn_rate.test) }}. Calibration learned in one season transfers imperfectly to another, so the gain is modest (log loss {{ ev.log_loss_uncalibrated }} to {{ ev.log_loss_calibrated }}). With more years of data, calibrating on the same season of the previous year would be the better fix.

7. Explanations

For each customer, each feature is reset to the training median and the customer is re-scored; the drop in risk is that feature's contribution. The top three positive contributions are shown as "signals". This is model-agnostic and cheap, but correlated features share credit.

8. Segments and actions

K-means on log-scaled recency, order count, spend and average order value. k is chosen from 3 to 6 by silhouette score (best k = {{ analysis.segments.k }}). Segments are named from their medians (recent vs lapsing, high vs low value). Suggested actions are written playbook rules, not model outputs.

9. Who to contact

The targeting curve adds up, customer by customer, risk × save rate × margin × the customer's typical 60-day spend, minus contact cost. It compares two orderings: by risk alone, and by expected value (risk × spend). Ranking by risk alone starts with high-risk customers who spend little, so its profit dips before it rises; ranking by expected value reaches a higher peak with fewer contacts. Only the risk comes from the model; the save rate, margin and cost are assumptions you set. Estimating the save rate properly requires an experiment (uplift modelling), which this project does not attempt.

10. What this does not show

  • One retailer, mostly wholesale buyers, 2009–2011. Results won't transfer directly to other businesses.
  • "No purchase in 60 days" is a proxy; some customers simply buy seasonally.
  • Risk is not the same as being persuadable: the highest-risk customers may be the least likely to respond.
